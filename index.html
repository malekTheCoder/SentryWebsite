[01] core monitoring

A menu bar you compose yourself.

CPU, GPU, memory, disk, network, thermals, battery: shown as values, icons, sparklines, bars or arcs. Drag to reorder. Per-module thresholds. Visibility rules, like only show battery when discharging.

Rendered strictly monochrome, so it stays legible on any wallpaper, with a single ! when something crosses critical.

Verdict first

One sentence, then a dense vitals table with per-module meters that stay grey until something needs you, and expandable rows. Everything in one glance. The dropdown never scrolls.

Three bands

The Dashboard window splits into Power, Activity and History. A floating liquid-glass switcher toggles Dashboard ↔ Settings. One window, no sprawl.

History that keeps

Per-metric charts from the last hour out to all-time, backed by a local SQLite time-series store with automatic rollups.

[02] sleep control

Stay awake exactly as long as the job takes.

Keep-awake for a duration, indefinitely, until battery drops below a threshold, while the CPU stays busy, or while a named process is running.

$ macstat awake --while-running claude
→ holding wake lock · pid 48213 · started 14:02
→ released automatically when the process exits

Point it at claude, codex, xcodebuild or node. Amphetamine, evolved for long-running agent work.

[03] ai-agent integration · the differentiator

Your agents can ask “is now a good time?”

A built-in MCP server exposes about twenty tools to Claude Code, Claude Desktop, Cursor, or any MCP client. Snapshots, battery health history, thermal state. And a preflight_check that returns a regression-based cool-down ETA, so agents schedule instead of poll.
