[01] core monitoring

A menu bar you compose yourself.

Nine modules — battery, CPU, GPU, Neural Engine, memory, disk, network, thermals, system — shown as values, icons, sparklines, bars or arcs. Drag to reorder. Per-module thresholds. Visibility rules, like only show battery when discharging.

Rendered strictly monochrome, so it stays legible on any wallpaper, with a single ! when something crosses critical.

Verdict first

One sentence, then a dense vitals table with per-module meters that stay grey until something needs you, and expandable rows. Everything in one glance. The dropdown never scrolls.

Three bands

The Dashboard window splits into Power, Activity and History. A floating liquid-glass switcher toggles Dashboard ↔ Settings. One window, no sprawl.

History that keeps

Per-metric charts from the last 24 hours out to six months, backed by a local SQLite time-series store with automatic rollups.

One glance, then one click

[02] sleep control

Stay awake exactly as long as the job takes.

Thirteen ways to hold the wake lock, not one. Pick a duration, hold it indefinitely, run it until a set time, or tie it to a condition and let it release itself.

Indefinitely15m30m 1h2h4h8h Until a timeUntil battery is low While CPU is busyWhile a process runs While a download is activeOn a schedule

The process field is prefilled with claude, so the menu reads “While claude runs”. Point it at codex, xcodebuild or node instead. Sentry also spots Claude Code’s own caffeinate and can take it over. Fixed durations and Indefinitely are free; the conditional modes are Pro. Amphetamine, evolved for long-running agent work.

[03] ai-agent integration · the differentiator

Your agents can ask “is now a good time?”

A built-in MCP server exposes twenty tools, with one-click setup for Claude Code, Claude Desktop, Codex CLI, Cursor, VS Code, Zed and Windsurf — or a config snippet for any other MCP client. Snapshots, battery health history, thermal state. And a preflight_check that fits a least-squares slope over recent temperature samples to return a cool-down ETA, so agents schedule instead of poll.

Per-tool permissions with writes off by default, a native confirmation dialog on every write, per-client rate limits and a live activity log. Behind that sits a guardrails layer: kill switch, per-client revocation, a battery floor, an on-battery write ban, quiet hours and thermal auto-revoke. Remote access is opt-in HTTP with bearer-key auth — it binds every interface, so put it behind your firewall.

[05] alerts

Fourteen rules, all editable.

Thresholds, sustained-duration conditions, per-rule quiet hours, a 30-minute default cooldown and a six-an-hour global rate cap. Add your own. Severity is never carried by colour alone.

[06] fans

Fans you can actually set.

Not a readout — a write. A root helper you install explicitly holds the only code in the project that can put a value into the SMC.

Every fan control stays disabled until you install the helper from Settings. It verifies its caller twice, expires on a heartbeat, and reverts to firmware control if anything goes quiet.

Apple Silicon only. Fixed-speed mode ships today; the curve editor does not, and the curve is read-only until it does. Fan readout works everywhere.

[07] design

Six themes, switchable from the dropdown.

Applied across the menu bar, dropdown and dashboard, and relayed to the Apple Watch. System and Translucent use real behind-window blur. Every one ships a light and a dark pair. Monospaced digits everywhere, so numbers never jitter.
